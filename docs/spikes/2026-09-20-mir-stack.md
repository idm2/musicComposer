Failed (no MSVC): `uv pip install madmom`, `uv pip install --no-build-isolation git+https://github.com/CPJKU/madmom`, `uv pip install [--no-build-isolation] vamp`.

Installing torch **first** from the cu128 index matters: later PyPI installs saw torch as already satisfied and did not replace it with a CPU build. In a real `pyproject.toml` this needs a `[tool.uv.sources]` / `[[tool.uv.index]]` entry pinning torch + torchaudio to the pytorch cu128 index.

## Chord recognition test

Test signal (`spikes/mir-stack/chord_test.py`): 16 s, 44.1 kHz, band-limited saw triads + bass root, C – Am – F – G, 4 s each.

### lv-chordia 1.1.0 — PASS (20.4 s wall incl. model load, 5-model ensemble)

```
{'start_time': 0.0,  'end_time': 0.02,  'chord': 'N'}
{'start_time': 0.02, 'end_time': 3.99,  'chord': 'C:maj'}
{'start_time': 3.99, 'end_time': 7.96,  'chord': 'A:min'}
{'start_time': 7.96, 'end_time': 12.0,  'chord': 'F:maj'}
{'start_time': 12.0, 'end_time': 16.02, 'chord': 'G:maj'}
```

All four chords correct, boundaries within 40 ms. Caveats:

- **Gotcha:** `chord_recognition()` resolves a *relative* path against its own package dir (`site-packages/`), giving `File not found`. Always pass an absolute path.
- **No confidence in the public output** — only start/end/label (Harte syntax, `chord_dict_name="submission"` = large vocabulary). CLAUDE.md requires confidence on every chord, so we will need to reach into the model's frame-level posteriors (the `mir/nn` + HMM decode internals) or derive a proxy (ensemble agreement across the 5 checkpoints, agreement with a chroma-template check from librosa). This is the main open design item.
- A clean synthetic triad is the easy case; it says nothing about 7ths/sus chords in a dense generated mix. Needs a real-audio accuracy check next.
- Prints `Inference: ...` lines to stdout per checkpoint — capture/suppress in the CLI.

## RECOMMENDATION

- **Chord recogniser: lv-chordia.** It is the only candidate that installs on this machine without a C++ toolchain, it is PyTorch/GPU-native, large-vocabulary (7ths, sus, inversions — the things librosa cannot do), and it got the test progression exactly right. Budget work to extract per-chord confidence from its internals, since the public API returns none.
- **Beat/downbeat tracker: beat_this** (`dbn=False`). Installs cleanly, runs on CUDA, no madmom needed. Pin to a commit hash rather than `main.zip` for reproducibility.
- **Drop madmom and vamp/Chordino from the plan** unless we are willing to make "install VS C++ Build Tools" a setup prerequisite. Not worth it: both replacements above are newer and stronger. If a second-opinion chord source is wanted for confidence, prefer a librosa chroma-template cross-check over Chordino.
- **Version pins:**
  - Python 3.11 (3.11.16 used), managed by uv.
  - `numpy==1.26.4` (i.e. **numpy<2**) — forced by basic-pitch's tensorflow 2.15 dependency. The whole stack (torch 2.11, librosa 0.11, numba 0.67, scipy 1.17, lv-chordia, beat_this) ran fine on it. Pin explicitly so resolver order doesn't matter.
  - torch/torchaudio `2.11.0+cu128` from `https://download.pytorch.org/whl/cu128`, configured as an explicit uv index so PyPI's CPU build never wins.
  - `protobuf<5` comes along with TF 2.15 — watch for conflicts if anything else wants protobuf 5+.
- **basic-pitch:** keep it, load the bundled `.onnx` model explicitly (`Model(str(ICASSP_2022_MODEL_PATH) + ".onnx")`) so inference uses onnxruntime. Follow-up worth 10 minutes: try `uv pip install --no-deps basic-pitch` + manual deps (onnxruntime, librosa, mir_eval, pretty_midi, resampy, scipy) to shed the ~1.5 GB tensorflow install and lift the numpy<2 pin. Not attempted in this spike.
- **faster-whisper:** works on CUDA float16 when torch is loaded in the same process. In the pipeline, `import torch` before constructing `WhisperModel` (or add `torch/lib` via `os.add_dll_directory`) rather than installing separate cuDNN DLLs. Verify once in a torch-free process if the transcribe stage is ever split out.
- **demucs:** declare numpy ourselves; demucs 4.1.0 doesn't.
- **Engraving:** `scoop install lilypond` (main bucket) is available now; MuseScore needs `scoop bucket add extras` first.
